**Q1.** What is the primary role of Large Language Models (LLMs) in a Retrieval Augmented Generation (RAG) system?

- To retrieve relevant documents from the knowledge base.
- To convert the user's question into an optimized search query.
- To generate responses using retrieved documents and the user's query.
- To integrate retrieved documents into its memory for future use.

✅ CORRECT ANSWER: To generate responses using retrieved documents and the user's query.

RAG = Retrieve → Augment → **Generate**. The retriever (BM25 / vector DB) finds the documents. The LLM is only the "G": it reads the documents + the question and writes the answer. It does NOT retrieve, and it does NOT remember the documents afterwards.

**Q2.** How does tokenization affect an LLM's handling of input text?

- It determines which documents are retrieved from the knowledge base.
- It splits text into word and sub-word pieces for embedding and processing.
- It applies basic text corrections before model input.
- It filters out low-value words to lower computational load.

✅ CORRECT ANSWER: It splits text into word and sub-word pieces for embedding and processing.

The LLM can't read raw text. It cuts text into tokens (whole words or pieces of words, e.g. "unhappiness" → "un" + "happiness"), and each token becomes a number/vector. Tokenization doesn't correct spelling or throw words away. (Rule of thumb from Module 1: 1 token ≈ 0.75 words.)

**Q3.** What happens when you set a lower temperature value when generating text with an LLM?

- The model produces more creative and unpredictable responses.
- The model processes inputs faster with less computational load.
- The model generates more predictable outputs by favoring higher-probability tokens.
- The model incorporates more specialized domain knowledge in its responses.

✅ CORRECT ANSWER: The model generates more predictable outputs by favoring higher-probability tokens.

Temperature is a "creativity dial". Low (near 0) = always picks the most likely next token = safe, repeatable answers. High = picks less likely tokens too = creative but unpredictable. It does not change speed or knowledge.

**Q4.** What are hallucinations in the context of Large Language Models?

- Errors in how the model processes unfamiliar or complex vocabulary.
- The model's ability to generate visual descriptions based on textual prompts.
- Content generated by the model that appears plausible but contains factual inaccuracies.
- Situations where the model exceeds its context window and fails to maintain coherence.

✅ CORRECT ANSWER: Content generated by the model that appears plausible but contains factual inaccuracies.

Hallucination = confident-sounding but WRONG (made up). This is exactly why we use RAG: give the LLM real documents so it doesn't invent facts (like asking about "Maheswar Reddy the alien" without any data).

**Q5.** What distinguishes 'few shot learning' from 'one shot learning' in the context of prompt engineering?

- The complexity of examples provided to the model.
- The number of example question-response pairs included in the prompt.
- The placement of examples within the system or user messages.
- The source of examples, with few shot using retrieved examples and one shot using hardcoded examples.

✅ CORRECT ANSWER: The number of example question-response pairs included in the prompt.

Zero-shot = 0 examples, one-shot = exactly 1 example, few-shot = a few (2, 3, 5...) examples. Only the COUNT is different.

**Q6.** What is the purpose of multi-headed attention in the Transformer architecture used by LLMs?

- To reduce the computational resources required for processing large documents.
- To allow the model to process multiple documents simultaneously.
- To let the model look at multiple kinds of relationships between words simultaneously.
- To separate factual information from opinions in the input text.

✅ CORRECT ANSWER: To let the model look at multiple kinds of relationships between words simultaneously.

Each "head" looks at the sentence in a different way at the same time (one head tracks grammar, another tracks who "it" refers to, another tracks meaning, etc.). It doesn't save compute and it isn't about multiple documents.

**Q7.** What is the specific function of the system prompt when using the messages format for prompting large language models (LLMs)?

- To store and maintain the conversation history between users and the LLM.
- To establish overall behavioral guidelines and contextual instructions for the LLM.
- To configure technical generation parameters such as temperature and max tokens.
- To identify which knowledge base documents should be retrieved.

✅ CORRECT ANSWER: To establish overall behavioral guidelines and contextual instructions for the LLM.

The 3 roles from Module 1: `system` = background rules ("You are a helpful assistant, answer short"), `user` = the question, `assistant` = the reply. Temperature and max_tokens are separate API settings, not the system prompt.

**Q8.** A company has three prototype chatbots. They feed the same challenging prompts to all three, then use a fourth, more advanced LLM to evaluate and score each response. What is this evaluation methodology commonly called?

- Retrieval-based benchmarking
- Model ensemble validation
- LLM-as-a-judge evaluation
- Comparative response filtering

✅ CORRECT ANSWER: LLM-as-a-judge evaluation

A stronger LLM acts as the "teacher" that grades the answers of other models. Cheaper and faster than humans reading everything.

**Q9. (SELECT ALL THAT APPLY - checkboxes)** Which of the following are accurate statements about how you can use LLM benchmarks and evaluation metrics to choose the appropriate model for your project?

- ☐ A fixed set of benchmarks can be used to assess model performance for any potential project.
- ☐ Benchmarks exist to measure concrete performance metrics like token generation speed, but not more subjective metrics like response quality.
- ☑ Benchmarks should be reproducible, meaning any variability in a model's score should come from the inherent randomness of the LLM and not the way the benchmark is calculated.
- ☑ Benchmarks are useful for tracking industry-wide improvements in LLMs as they rapidly develop new capabilities.

✅ CORRECT ANSWERS: the 3rd and the 4th.

- 1st is FALSE: no single fixed benchmark fits every project. You should test with your own use case.
- 2nd is FALSE: there ARE benchmarks for quality too (not only speed).
- 3rd TRUE: a fair benchmark gives the same score calculation every time, so a different score means the MODEL changed, not the scoring.
- 4th TRUE: benchmarks let the whole industry compare progress over time.

**Q10. (SELECT ALL THAT APPLY - checkboxes)** Which of the following accurately describes the benefits of building agentic LLM workflows?

- ☑ Inside an agentic workflow different models can be assigned specialized subtasks they are best suited to.
- ☐ Agentic workflows replace the need to use a retriever in your RAG application.
- ☑ Agentic applications can interact with their environment, for example by performing a database search or interacting with an outside tool over an API.
- ☑ Simple agentic components like a router LLM can help a RAG application decide if a retrieval step is necessary or if a language model can respond to a prompt without it.

✅ CORRECT ANSWERS: 1st, 3rd and 4th.

- 2nd is FALSE: agents don't replace the retriever. The retriever is often one of the TOOLS the agent uses.
- 1st/3rd/4th TRUE: split work between specialist models, use tools (database, API), and use a "router" to decide when retrieval is needed.

## Quick memory cheat-sheet

| Topic | One-line memory |
|---|---|
| LLM's job in RAG | the "G" - Generate the answer from retrieved docs |
| Tokenization | text → word / sub-word pieces |
| Low temperature | predictable, safe, repeatable |
| Hallucination | plausible but wrong - RAG helps reduce it |
| Few-shot vs one-shot | only the NUMBER of examples differs |
| Multi-head attention | many kinds of word relationships at once |
| System prompt | rules/behavior for the LLM |
| LLM-as-a-judge | a stronger LLM grades other LLMs |
| Benchmarks | track progress + reproducible, but not one-size-fits-all |
| Agentic workflows | specialist models + tools + router; they don't replace the retriever |
